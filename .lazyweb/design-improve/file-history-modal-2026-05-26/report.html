Design Improvement: File History Modal

agentic-git-sync · 2026-05-26

TL;DR: The biggest opportunity is switching from a vertical stack (list on top, diff below) to a horizontal split (list left, diff right). This is the dominant pattern in every serious diff viewer — VS Code, GitHub, GitLens, SourceTree — because it keeps the commit list visible while reading a long diff.

Current State

The modal uses a top-bottom layout: commit list fills the top, and a diff pane appears below when a commit is selected. The list uses a 4-column grid where hash, message, author, and time all receive equal visual weight.

Improvement Ideas

1. Horizontal Split: List Left · Diff Right ⭐ Highest Impact

Change the modal from a vertical (top-bottom) to a horizontal (left-right) layout. The commit list becomes a fixed-width left panel (~280px); the diff occupies the remaining right space.

Why this works: When reading a diff you inevitably scroll. In the current layout the commit list disappears immediately. In a left/right split the list stays anchored — which is exactly why VS Code, GitHub, GitLens, SourceTree, and Tower all use this layout for history views.
┌───────────────────────────────────────────────────────────┐ │ ⏱ 文件历史 · A0-Inbox/中年男人的宿命.md │ ├──────────────────┬────────────────────────────────────────┤ │ 12d08a4 2h ago │ 12d08a4 · sync: 2026-05-26T03:26… │ │ e6dbb01 16h ago │ Jakob He · May 26 [⎘] │ │▶d394360 17h ago │────────────────────────────────────────│ │ 94bf4d8 17h ago │ @@ -7,3 +7,6 @@ │ │ 7606696 17h ago │ 嗯嗯嗯 │ │ 9c21a76 17h ago │ 哦哦哦 │ │ ff83965 17h ago │ 哈哈哈 │ │ 7855e5e 17h ago │ + │ │ 37da56f 17h ago │ +明天会下雨。 │ │ │ +明天我吃饭！ │ │ │ │ ├──────────────────┴────────────────────────────────────────┤ │ [关闭] │ └───────────────────────────────────────────────────────────┘

Implementation: Replace the flex-column layout with display: grid; grid-template-columns: 280px 1fr. Give the list panel overflow-y: auto and the diff panel its own independent scroll context.

2. Keyboard Navigation (↑↓ through commits)

Add ArrowUp / ArrowDown key handling so users can step through commits without reaching for the mouse. This is table-stakes for developer tools.

Why this works: After clicking into the modal, users naturally want to keyboard-navigate. VS Code's Timeline panel, SourceTree, and GitHub Desktop all support ↑↓. In a narrow list panel (see idea #1) this becomes even more natural — the list feels like a sidebar to navigate.
// In onOpen(), after renderList():
this.scope.register([], "ArrowDown", () => {
  const next = (this.anchorIdx ?? -1) + 1;
  if (next < this.commits.length) {
    this.anchorIdx = next; this.rangeEndIdx = null;
    this.renderList(); void this.updateDiff();
  }
  return false;
});
this.scope.register([], "ArrowUp", () => {
  const prev = (this.anchorIdx ?? this.commits.length) - 1;
  if (prev >= 0) {
    this.anchorIdx = prev; this.rangeEndIdx = null;
    this.renderList(); void this.updateDiff();
  }
  return false;
});

Use Obsidian's this.scope (available on Modal) so shortcuts don't conflict with global bindings.

3. Add a +N −N Stat Bar in the Diff Header

Between the commit info bar and the diff content, show a one-line stat bar with additions and deletions count. This gives users a "how big is this change?" signal before reading.

Why this works: GitHub, GitLens, and Tower all surface this stat immediately. For long files a change might add 50 lines but the actual diff is small — or vice versa. The stat bar sets the right expectations before the user starts scrolling.
┌─────────────────────────────────────────────────────┐ │ 12d08a4 sync: 2026-05-26… Jakob He · May 26 [⎘] │ │ ████░░░░░░░░░░░░░░░░ +3 additions −0 deletions │ ├─────────────────────────────────────────────────────┤ │ @@ -7,3 +7,6 @@ │ │ 嗯嗯嗯 │

Implementation: Parse the diff text for lines starting with + (excluding +++) and - (excluding ---) to get counts. The colored bar is a proportion fill: width: ${adds/(adds+dels)*100}% green, remainder red.

4. Visual Hierarchy in the Commit List

The current 4-column grid gives equal weight to hash, message, author, and time. The commit message should be the primary reading target; hash and author are secondary metadata.

Why this works: GitLens, GitHub Desktop, and Tower all use a single dominant line for the message with muted secondary text. The current design makes the bright teal hash links draw the eye away from the most important column.
Current: 12d08a4 sync: 2026-05-26T03:26:01.016Z Jakob He 2h ago (all columns equal weight, hash dominates with teal color) Proposed: sync: 2026-05-26T03:26:01.016Z ················ 12d08a4 2h ago (message bold/primary, hash + time muted, no author column needed)

Remove the author column from the list (visible in the diff info bar already). Let the message fill available space with flex: 1; overflow: hidden; text-overflow: ellipsis. Style hash and time as color: var(--text-muted); font-size: 12px.

5. Line Numbers in the Diff

Show before/after line numbers for each diff line. This gives spatial context ("this change is on line 47") and is present in every serious diff viewer.

│ │ @@ -7,3 +7,6 @@ 7 │ 7 │ 嗯嗯嗯 8 │ 8 │ 哦哦哦 9 │ 9 │ 哈哈哈 │ 10 │ + │ 11 │ +明天会下雨。 │ 12 │ +明天我吃饭！

Implementation: Parse the @@ -A,B +C,D @@ hunk header to extract start line numbers, then increment two counters (oldLine, newLine) as you render. Use display: grid; grid-template-columns: 36px 36px 1fr per row. Skip line number increment for deleted/added lines on the respective side.

What's Working

  • Shift-click range selection — elegant and powerful; keep exactly as-is
  • Range info bar ("7855e5e → 9c21a76 · 3 commits combined") — clear and useful
  • Diff syntax coloring — the green/red/hunk/meta coloring is correct and readable
  • Modal size — 95vw × 90vh is appropriate for a diff viewer
  • Copy hash button — good utility, correctly positioned in the info bar

Reference Pattern

Deepnote's version history screen (found in Lazyweb DB) uses a horizontal split: left sidebar lists chronological versions with timestamps and autosave labels; right pane shows the selected version's content. This directly validates the horizontal split pattern for "history + preview" UI — and Deepnote is closer in spirit to Obsidian (a note-taking tool with version history) than a code editor is.
